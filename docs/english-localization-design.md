## 1. 목적과 범위

영어 성경 KJV · BSB 를 앱에 넣어 번역본을 바꿔 필사하고, 앱 화면을 영어로 현지화한다. **한국어 필사와 영어 필사는 섞이지 않는다.**
영어 화면은 영어 성경 없이는 쓸모가 적어 한 작업으로 묶었다(결정 2).

| 구분 | 2.1.0 |
|---|---|
| 성경 | 개역개정(지금) + **KJV · BSB**. 헤더 제목을 눌러 번역본을 고른다(결정 4 · 19) |
| 화면 | 앱 UI 영어 현지화 — **기기 언어를 따른다**(결정 3). 앱 언어만 따로 바꾸려면 설정 › 화면 › 언어가 iOS 앱별 언어 화면을 연다(결정 20, §8-5). 영어 앱 이름은 **Carve**(결정 8) |
| 저장 | 스키마 · 마이그레이션 · CloudKit 설정 변경 없음. 영어 행은 권 이름 접두로 구분한다(§3, 결정 1) |
| 배포 | **영국을 빼고 배포한다.** 출시 때 App Store Connect 배포 국가에서 영국을 뺀다(KJV 영국 권리 — §2-1). **2.0.0 이 지금 영국에 나가 있는지 출시 전에 확인한다** — 나가 있으면 영국 사용자는 2.1.0 으로 업데이트하거나 다시 받을 수 없게 된다 |
| 범위 밖 | ESV · NIV(§2-1), 한영 대조 화면, 자동 번역, App Store 영어 메타데이터(결정 8), 영어 글꼴 추가(결정 12 — M1 뒤 후속 판단) |

## 2. 판본 · 권리 · 출처

### 2-1. 권리

- **KJV 만 영국 스토어에서 숨기기 — 기각.** 본문이 앱 파일 안에 있으면 고르기에서 숨겨도 영국에 본문을 배포한 셈이라 근거가 약하다.
  영국이 아닌 스토어에서만 내려받게 하면 확실하지만 구현이 늘어난다.
- **ESV · NIV — 범위 밖.** 정식 라이선스는 단체 · 사역 기관에만 나온다(지금은 개인 명의). ESV 는 AI LLM 과 연동하는 프로젝트를 지금 승인하지 않는다.
  ESV API 는 광고 · 인앱 구매가 있는 앱을 상업으로 보고, 기기 안 저장을 500절로 묶으며, 키를 앱에 넣을 수 없어 중계 서버가 필요하다(Carve 에는 CloudKit 말고 서버가 없다).
  즐겨찾기 · 위젯이 본문 사본을 저장하는 구조와도 맞지 않는다.
- **WEB — 기각(2026-10-02).** 기본판이 하나님의 이름을 "Yahweh" 로 쓰고, 신약이 KJV 와 같은 다수 사본 계열이며, 판본이 여럿이고, 앱에 "WEB" 으로 적으면 '웹' 으로 읽힌다.
  KJV 하나(고어체 — 영어가 모국어가 아닌 사용자에게 부담) · BSB 하나(국내에 이름이 알려지지 않음)도 기각했다. 두 판본은 문체(고전 · 현대)와 본문 계열(TR · 비평 본문)이 서로 보완한다.

### 2-3. 변환 규칙

- **KJV:** 책 제목 · 쪽 꼬리말(`PAGE …` · `MERGEFORMAT` · 대문자 책 이름 줄) · 서문 · 헌정문 · 서신 끝 맺음말(14곳) · `¶` 를 뺀다.
  빌레몬서 1:2 를 1:1 줄에서 나눈다. 시편 표제(116) · 119편 자모(Aleph … Tav, 22)는 소제목이다.
- **BSB:** 각주(`\f`) · 교차 참조 줄(`\r`) · 머리 표지를 뺀다. `\s1` · `\s2` 소제목, `\d` 시편 표제, `\qa` 자모(히브리 글자 줄은 빼고 이름만),
  `\ms` 시편 권(Book I … V — 뒤의 범위 줄은 뺀다)은 소제목이다. 단락 · 시 표지는 공백으로 잇고 `\wj` 는 글자만 남긴다.
- 출력은 개역개정과 같은 줄 문법이다(§5). 소제목이 여럿이면 `<…>` 하나 안에 LF 로 잇는다 — 예: BSB 시 3:1 `<Deliver Me, O LORD!⏎A Psalm of David, …>`.

## 3. 번역본 귀속 (결정 1 · 동결)

### 3-1. 규칙

| 행 | `titleName` | `translation` 열 | 읽을 때 번역본 |
|---|---|---|---|
| 개역개정 — 지금 · 앞으로 | `BibleTitle.rawValue`(예 `1-01Genesis.txt`) — **지금과 같다** | `.NKRV`(옛 행은 nil 일 수 있다) | NKRV |
| KJV · BSB | `"<Translation.rawValue>-<BibleTitle.rawValue>"`(예 `KJV-1-01Genesis.txt`) — 본문 리소스 파일명과 같다 | **늘 nil** | 접두의 번역본 |
| 접두를 모르거나 권 이름을 모름 | — | — | 풀지 못함(nil) — 지금처럼 건너뛴다 |

- **SwiftData 의 `translation` 열**(`BibleDrawing` · `BiblePageDrawing` · `FavoriteVerse` · `VerseDrawingVersion`)**에는 `.NKRV` 나 nil 만 쓴다. 영어 값은 절대 쓰지 않는다.**
  이미 나간 2.0.0 기기가 모르는 열거값을 디코딩하다 죽을 수 있기 때문이다(U3 — 미검증, [데이터 호환성 결정](./data-compatibility-decision.md) §2).
- 행을 읽을 때 번역본은 **`titleName` 접두로 먼저 정한다.** 접두가 없으면 열이 nil 이든 `.NKRV` 든 NKRV 다.
- 짓고 푸는 곳은 Domain `StoredBookKey`(`Domain/Domain/Sources/Model/StoredBookKey.swift`) **하나뿐**이다. `titleName` 문자열을 직접 이어 붙이거나 자르지 않는다.

  | API | 뜻 |
  |---|---|
  | `titleName(for: BibleChapter) -> String` · `titleName(title:translation:) -> String` | 행에 쓸 권 이름. NKRV 는 rawValue 그대로, 그 밖은 `"<번역본>-<rawValue>"` |
  | `decode(_ titleName: String) -> (title:, translation:)?` | 아는 번역본 접두 + rawValue → 그 번역본, 접두 없는 rawValue → `.NKRV`, 그 밖 → nil |
  | `translationColumn(for: Translation) -> Translation?` | `.NKRV` → `.NKRV`, 그 밖 → nil |

- `"NKRV-"` 접두는 만들지 않는다 — 개역개정 행 형식이 지금과 같아야 구버전 · 이전 일치 검사(`LegacyMigrationContentMatcher`) · 백업이 그대로다.
- business id(`<권>.<장>.<절>.<초>`)는 `rowUUID` 가 없을 때의 행 키일 뿐 어디서도 쪼개 읽지 않는다(백업 설계 §4-3) — 권 자리에 무엇이 들어가도 동작은 같다.
- 같은 규칙이 조회 술어에 그대로 적용된다 — 장 · 절 · 행 찾기의 `titleName == …` 를 `StoredBookKey.titleName(for:)` 로 바꾸면 번역본이 갈린다.
  차트 · 최근 기록(`updateDate` 술어)은 모든 번역본을 읽고 행마다 `decode` 로 번역본을 정한다.

### 3-2. 구버전 동작 근거

2.0.0 = `main` `118715de`, 1.3.0 = `49f2dc27`(App Store 출시본). 영어 행은 구버전에게 **모르는 권 이름의 행**이다.

| 경로 | 2.0.0 · 1.3.0 의 동작 | 영어 행 |
|---|---|---|
| 장 조회 · 저장 · 지우기 · 이전 필사 · 장 칠하기 · 즐겨찾기 조회 | 술어 `titleName == title.rawValue` | 맞지 않아 **보이지 않고 고치지도 않는다** |
| 차트 장별 수 · 최근 장 | `guard let …, let title = BibleTitle(rawValue:)` 로 건너뛴다(2.0.0 `DrawingChartFeature.swift:192-195` · `:224-227` · `:321-323`, 1.3.0 `:175` · `:207` · `:304`) | 빠진다 |
| 즐겨찾기 목록(2.0.0 — 1.3.0 에는 즐겨찾기가 없다) | `guard let titleName, let title = BibleTitle(rawValue:)`(2.0.0 `SwiftDataFavoriteVerseRepository.swift:147`) | 빠진다 |
| `translation` 열 디코딩 | 2.0.0 의 즐겨찾기(`translation ?? .NKRV`) · `LegacyMigrationContentMatcher` 가 getter 를 부른다 | 영어 행은 nil 이라 디코딩할 모르는 값이 없다 — **U3 를 피한다** |
| 차트 날짜별 절 수 · 주간 평균 | `updateDate` 술어로 모든 행을 센다 | **센다** — 영어 필사도 그날 쓴 절 수에 든다 |
| 주간 요약 「최근 절」 | `BibleTitle(rawValue:) ?? .genesis` · `titleChapter ?? 1`(2.0.0 `DrawingChartFeature.swift:208-220`, 1.3.0 `:190-202`) | ⚠️ **창세기로 보인다** — 최근 5행 안의 영어 행이 「창세기 <장>장 <절>절」 로 보이고 누르면 그 위치를 연다. 창세기에 없는 장(51 이상)이면 본문 로더가 빈 목록을 돌려준다. 쓰기는 없다(코드 읽기로 확인, 실행 미확인 — M4) |
| 모든 필사 삭제 | 권을 가리지 않고 `BibleDrawing` 행을 모두 지운다 | 영어 필사도 지운다 — 「모든 필사」 의 뜻과 같다 |

- `BibleTitle(rawValue:)` 를 강제 언랩하는 곳은 2.0.0 · 1.3.0 제품 코드에 없다(`git grep`, 2026-10-06).
- 기기 안 초안 · 위젯 payload 는 동기화하지 않아 다른 기기의 구버전에 가지 않는다(§3-4).
- **이 동작에 기댄다.** 실제 두 기기 공존은 M4 가 출시 전 관문으로 확인한다(§9).

### 3-4. SwiftData 밖의 번역본

`translation` 열 규칙(§3-1)은 SwiftData 행에만 걸린다. 동기화하지 않는 곳과 앱이 읽는 파일 형식에는 번역본의 실제 값을 쓴다.

| 저장 | 번역본 표기 | 동기화 |
|---|---|---|
| `@Shared(.appStorage("title"))` — 지금 장 | `BibleChapter` JSON 의 `translation` 키(§4) | 기기 설정 — 하지 않는다 |
| 기기 안 초안 `VerseDraftKey` | `"KJV"` 등 실제 값(파일 이름 포함) | 하지 않는다(로컬 파일) |
| 위젯 payload | `Translation.rawValue` · 약칭 문자열 | App Group — 기기 안 |
| 백업 파일 `BackupVerseKey.translation` | 영어 행은 **`titleName` 접두에서 온** `"KJV"` · `"BSB"`, 개역개정 행은 열 값 그대로(nil 은 null) — [백업 설계](./backup-import-design.md) §2-4 | 파일 |

## 4. 장 식별 — `BibleChapter.translation` (결정 13)

- `BibleChapter` 에 `translation: Translation` 을 넣는다. `init(title:chapter:translation: Translation = .NKRV)`.
  - Codable: `translation` 키가 없으면 `.NKRV` — 옛 `@Shared("title")` JSON 과 `-UITestChapter` JSON(`{"title":"1-19Psalms.txt","chapter":119}`)을 그대로 읽는다.
  - `==` · `hash` 는 title · chapter · translation 셋 다다(지금 `==` 는 title · chapter 만 본다 — `BibleChapter.swift:14-16`).
  - 장을 여는 경로 · 즐겨찾기 · 위젯 · 차트 · 초안이 번역본을 따로 인자로 받지 않고 장과 함께 나른다. 기각: 별도 키 + 함수마다 번역본 인자(빠뜨리기 쉽다).
- **지금 번역본 = `@Shared(.appStorage("title"))` 에 저장된 장의 `translation`.** 별도 저장 키는 없다. 기기마다 저장한다 — 다른 iPad 는 따라오지 않는다(결정 4).
- **처음 기본값:** `BibleChapter.initial(preferredLanguages: [String])` — 첫 언어가 `"ko"` 로 시작하면 개역개정 창세기 1장, 아니면(빈 목록 포함) BSB 창세기 1장(결정 4).
  저장값이 있으면 그대로다 — 기존 사용자는 개역개정을 유지한다. `BibleChapter.initialState` 는 개역개정 그대로 둔다.
  앱의 `@Shared("title")` 기본값은 CarveFeature `BibleChapter.firstLaunch` 이고, 기기 선호 언어를 의존성 `\.preferredLanguages` 로 읽어 이 함수를 부른다(시험이 언어를 바꿔 넣는다).
- `Translation`(`Domain/Domain/Sources/Model/Translation.swift`) — `enum Translation: String, Codable, Sendable, CaseIterable { case NKRV, KJV, BSB }`

  | 멤버 | NKRV | KJV | BSB |
  |---|---|---|---|
  | `displayName`(약칭 · 현지화) | ko 「개역개정」 · en 「NKRV」 | KJV | BSB |
  | `fullName`(현지화) | ko 「개역개정」 · en 「New Korean Revised Version」 | King James Version | Berean Standard Bible |
  | `resourceFileName(for:)` | `title.rawValue` | `KJV-<rawValue>` | `BSB-<rawValue>` |
  | `textEncoding` | CP949(CFStringEncoding `0x0422`) | UTF-8 | UTF-8 |
  | `languageCode` | `"ko"` | `"en"` | `"en"` |

- 공개 API 를 바꿀 때 기존 시그니처를 지우지 않는다 — `BibleChapter`(번역본 포함)를 받는 경로로 흐르게 하거나 `translation: Translation = .NKRV` 기본값 인자를 더한다.

## 5. 본문 형식 · 로더 (결정 10)

| 항목 | 개역개정 | KJV · BSB |
|---|---|---|
| 위치 | `Shared/Resources/Resources/BibleText/NKRV/<rawValue>` | `Shared/Resources/Resources/BibleText/{KJV,BSB}/<번역본>-<rawValue>` |
| 파일명 | `1-01Genesis.txt` | `KJV-1-01Genesis.txt` · `BSB-1-01Genesis.txt` |
| 인코딩 | CP949 | **UTF-8** |
| 줄 구분 | CR, 파일 끝 CR 없음 | 같다 |
| 줄 문법 | `장:절 [<소제목>] 본문`, 합쳐진 절 `장:절-절`(11곳), 절 번호 없이 잇는 줄 `장:본문`(43곳), 시편 권 `1:제일권` | `장:절 [<소제목>] 본문` 만. 시편 권(Book I … V)은 소제목 |
| 없는 절 | 줄이 없다(예 행 24:7) | **줄이 없다**(§2-4) — 번역본에 없는 절은 원문 그대로 비운다 |

- **파일명에 번역본을 붙이는 이유:** 리소스는 번들 루트에 **평평하게** 복사된다. 폴더만 나누고 같은 파일명을 두면 겹친다(「Multiple commands produce」).
  [데이터 호환성 결정](./data-compatibility-decision.md) §4-3 의 「번역본 차원은 파일명이 아니라 경로로」 는 이 사실로 바뀌었다 — 폴더로 나누고 파일명에도 번역본을 붙인다.
  이 파일명은 영어 행의 `titleName` 과 같은 문자열이다(§3-1).
- 로더 `ResourceBibleTextClient`(`Domain/Domain/Sources/BibleText/BibleTextClient.swift`)는 `chapter.translation` 의 `resourceFileName(for:)` · `textEncoding` 으로 읽는다.
  인터페이스 `fetch(chapter:)` 는 그대로다(장에 번역본이 있다).
- 파서 `BibleChapterTextParser` · `BibleTextLine` 은 바꾸지 않는다. 시편 권 표 `psalmBookLabels` 는 개역개정의 `1:제일권` 줄에만 걸리고 영어 줄에는 그런 줄이 없다.
- 시험(실제 리소스): KJV 31,102절 · BSB 31,086절 · 66권 장 수가 개역개정과 같음(1,189), BSB 에 없는 16절, KJV 요삼 1장 14절 · 고후 13:14 · 행 24:7,
  시 3:1 · 119:1 · 119:9 소제목, 빌레몬서 1:1 · 1:2 분리, 마 17:22 의 BSB 소제목, 둥근 따옴표 · 대시가 깨지지 않음. 개역개정 파서 시험은 그대로 통과한다.

## 6. 표시 규칙 (결정 3 · 11)

### 6-1. 권 이름 · 장절 — 앱(기기) 언어를 따른다

한국어 기기는 KJV 를 봐도 「창세기 1장 1절」, 영어 기기는 개역개정을 봐도 「Genesis 1:1」 이다. 번역본 언어가 아니라 **기기 언어**다(사용자 선택 — 추천안은 번역본 언어였다).

| 표기 | ko | en |
|---|---|---|
| 장 | 창세기 1장 | Genesis 1 |
| 절 | 창세기 1장 1절 | Genesis 1:1 |
| 절 범위 | 신명기 6장 18-19절 | Deuteronomy 6:18-19 |
| 시편 참조 | 시편 23장 1절(지금 앱 표기 그대로) | **Psalm** 23:1(단수) |
| 권 목록 이름 | 시편 | **Psalms** |
| 번역본 약칭을 붙인 참조 | 창세기 1장 1절 · KJV | Genesis 1:1 · KJV |

- 권 이름은 `BibleTitle.localizedName`(Domain 카탈로그에 66권 ko · en — en 은 표준 이름 Genesis … 1 Samuel … Song of Solomon … Revelation),
  권 검색용 고정 영문은 `englishName` 이다. 참조 문자열은 **`BibleReference` 로만** 만든다(`Domain/Domain/Sources/Model/BibleReference.swift`).
- `koreanTitle()` 의 호출부는 레이어 4 에서 옮겼다 — 제품 코드에서는 Debug(레이아웃 HUD)에만 남았다. 함수는 권 이름 카탈로그 키의 원문이라 그대로 둔다.

### 6-2. 번역본 약칭

- 약칭은 참조 뒤에 「 · KJV」 처럼 붙인다.
- **개역개정 약칭은 자리에 따라 다르다(결정 17, 2026-10-12).** 2.0 부터 번역본 이름을 적어 온 자리는 그대로 두고, 2.1 에 새로 번역본이 섞이는 목록은 KJV · BSB 만 붙인다.

  | 자리 | 개역개정 | KJV · BSB |
  |---|---|---|
  | 이미지 저장의 출처 · 위젯 · 필사 헤더 · 즐겨찾기 카드 · 위젯 설정 목록 — 2.0 부터 「개역개정」 을 적어 왔다 | 「개역개정」 그대로 | 약칭 |
  | **섞이는 목록** — 차트 최근 절 · 최근 장 · 가장 많이 쓴 장(주간 요약), 확인이 필요한 필기의 자리 표기와 결과 안내 | **생략** — 「창세기 1장 1절」 | 「창세기 1장 1절 · KJV」 |

  - 이유: 레이어 3(t3c)이 결정 11 대로 섞이는 목록의 개역개정에도 「 · 개역개정」 을 붙여, 영어 필사가 없는 한국어 사용자 화면까지 바뀌었다 — 사용자가 개역개정 생략을 골랐다.
    반영은 레이어 5 t5a 다(`RecentVerseItem` · `DrawingWeeklySummaryView` · `DraftRecoveryCopy.place` · `DraftRecoveryFeature`).
- 번역본 고르기는 **헤더 제목 메뉴**다(결정 19, 2026-10-12 — 처음에는 디자인 시안 `k3-sidebar-native-ad.svg` · `j2-dark-navigation.svg` 의 사이드바 하단 「개역개정 ⌄」 자리였으나 어색해 옮겼다). 제목을 누르면 메뉴가 열리고 항목은 약칭과 전체 이름을 함께 보인다. 부제 끝의 ⌄ 가 누를 수 있음을 알린다. 제목은 더 이상 탐색 열을 열지 않는다 — 탐색은 서재 버튼, 실행 인자 `-UITestRoute navigation` 은 `CarveNavigationFeature.openNavigation`.

### 6-3. 「성경 본문 출처」 화면

설정 › 앱 정보에서 들어간다(`Feature/SettingsFeature/Sources/Details/BibleSource/`). 번역본마다(`Translation.allCases` 순서) 이름 · 판 · 권리 · 출처를 보인다.

| 번역본 | 보이는 것 |
|---|---|
| 개역개정 | 항목만 둔다. **권리 문구는 허락 근거를 확인한 뒤 채운다** |
| KJV | King James Version · 1769 표준판 본문 · 영국 밖에서 공개 도메인 · 본문 사본 출처 `github.com/christislord12/kjv-txt-files` |
| BSB | Berean Standard Bible · CC0 1.0(2023-04-30 공개 도메인 헌정) · berean.bible · 본문 사본 출처 `bereanbible.com/bsb_usfm.zip` |

## 7. 번역본 전환 (결정 9)

- **같은 권 · 장 · 절을 유지한다.** 그 번역본에 없는 절이면 **바로 앞 절**로 간다 — 예: 개역개정 마 17:21 에서 BSB 로 바꾸면 17:20.
  장 수는 세 번역본 모두 1,189장으로 같아 장이 없는 경우는 없다.
- 전환은 **장 이동과 같은 경로**를 탄다 — 캔버스 저장 flush → 새 장 load. 저장 대기 중이던 획은 원래 번역본의 장으로 간다.
- 지금 번역본은 `@Shared("title")` 의 장 하나로 바뀐다(§4). 레이아웃 측정 · 캔버스 · 즐겨찾기 읽기는 `BibleChapter`(번역본 포함)로 갈린다.
  `ChapterLayoutSignature` · `DrawingLayoutMetadata` · 저장된 레이아웃 형식은 바꾸지 않는다.
- 다른 화면에서 절로 들어오는 경로는 **그 항목의 번역본**으로 연다 — 즐겨찾기 「말씀으로 이동」 · 주간 요약 · 최근 기록 · 위젯 딥링크.
  위젯 링크의 번역본을 모르면 개역개정으로 바꾸지 않고 **링크를 무시한다.**

## 8. 현지화 규칙 (결정 5 · 6 · 7 · 8 · 12)

### 8-1. 카탈로그

- 모듈마다 `Resources/Localizable.xcstrings` 하나다. **`sourceLanguage` 는 `ko`, 키는 한국어 문장 그대로**다. 같은 태스크가 영어(en)도 채운다(state `translated`).

  | 모듈 | 카탈로그 |
  |---|---|
  | App | `App/CarveApp/Resources/Localizable.xcstrings` · `InfoPlist.xcstrings` |
  | 위젯 | `App/CarveApp/Widget/Resources/Localizable.xcstrings` · `InfoPlist.xcstrings` |
  | CarveFeature · ChartFeature · SettingsFeature | `Feature/<모듈>/Resources/Localizable.xcstrings` |
  | UIComponents | `Supports/UIComponents/Resources/Localizable.xcstrings` |
  | Domain | `Domain/Domain/Resources/Localizable.xcstrings` — 권 이름 · 참조 형식 · 번역본 이름 |

- 이유: 컴파일러 자동 추출이 모듈 단위로 돌고, 태스크가 자기 모듈 카탈로그만 고쳐 겹치지 않는다.
  기각: `Shared/Resources` 한 곳 + 의미 키(모든 작업이 한 파일을 만지고 자동 추출이 안 된다).
- 빌드 설정은 이미 켜져 있다 — `developmentRegion: "ko"` · `defaultKnownRegions: ["en", "ko"]` · `LOCALIZATION_PREFERS_STRING_CATALOGS` · `STRING_CATALOG_GENERATE_SYMBOLS`
  (`Plugins/ProjectDescriptionHelpers/Project+Templates.swift`). 리소스가 없던 모듈(Chart · Settings · UIComponents · Domain · 위젯)은 레이어 0 에서 매니페스트에 resources 를 더한다.
  모듈은 static framework 라 리소스가 있으면 `Bundle.module` 이 생긴다.

### 8-2. 쓰는 법

| 경우 | 쓰는 법 |
|---|---|
| SwiftUI 리터럴 | `Text("…", bundle: .module)`. `Button` · `Label` · `Section` · `navigationTitle` · `accessibilityLabel` 등은 bundle 을 받는 이니셜라이저나 `Text(…, bundle:)` 로 |
| `String` 으로 흐르는 문구(Copy enum · 컴포넌트 파라미터 · Popup · Action 페이로드 · UIKit 라벨) | `String(localized: "…", bundle: .module, comment: "…")` |
| TCA | `TextState("…", bundle: .module)` |
| 단위 · 수(장 · 절 · 개 · N번째) | 카탈로그 형식 문자열(`%lld`)과 **복수형 변형** — 문자열을 이어 붙이지 않는다 |
| 날짜 | 기기 로케일 `FormatStyle`. 고정 `ko_KR` 포맷(지금 5곳)을 없앤다 |
| 앱 이름 | ko 「새기다」 · en **「Carve」** — 홈 화면 · 위젯(`InfoPlist.xcstrings` 의 `CFBundleDisplayName`) · 앱 안 로고 |

- **옮기지 않는 것:** 로그(`Logger` · `Log` · `print`) · `#if DEBUG` · `Debug` 폴더 · 프리뷰 · 컴포넌트 갤러리 · 분석 이벤트 이름 · 저장 키 · 메일 제목의 `UserFeedback` rawValue.
- 영어 문구는 짧고 평이하게 쓴다. iPad 사이드바 · 팔레트처럼 폭이 좁은 곳에서 잘리지 않게 한다.
- 영어 문구 검토(결정 7): 작업이 끝나면 `xcodebuild -exportLocalizations` 결과로 화면별 한영 대조표를 만들어 사용자 검토를 받고, 고친 문구는 별도 커밋으로 반영한다.
- 기계 검사: `.swiftlint.yml` 의 `localized_text_needs_bundle`(error — 한글이 든 `Text` · `Button` · `Label` · `TextState` 리터럴에 `bundle:` 이 없는 경우, 레이어 5 t5a 가 더한다).
- 코드를 쓸 때의 규칙(카탈로그 · 번들 · 수 · 날짜 · 시험 언어 · 번역본 귀속)은 룰북 `.codex/skills/carve-rulebook/references/localization.md` 에 옮겼다.

### 8-3. 시험 언어 (결정 6)

- **시험은 ko-KR 로 돈다.** 자동 생성 워크스페이스 스킴과 프로젝트 자동 스킴의 시험 언어 · 지역을 `ko` · `KR` 로 고정한다(`Workspace.swift` · `Project+Templates.swift`).
  새로 만드는 시뮬레이터는 기본이 영어라 고정하지 않으면 결과가 기기마다 달라진다.
- 기존 한국어 단언(약 120줄 · 26개 파일)과 UI 테스트의 한국어 라벨 찾기는 그대로 둔다.
- 영어 확인은 **언어를 실제로 고르는 경로**로 명시한다. `String(localized:bundle:locale:)` 의 locale 은 보간 값 서식에만 쓰이고 언어를 고르지 않는다
  (레이어 1 에서 맥 · iOS 26.2 시뮬레이터로 확인). `LocalizedStringResource(…, locale: Locale(identifier: "en"), bundle: .atURL(Bundle.module.bundleURL))` 를
  `String(localized:)` 로 풀거나, locale 을 받는 API(`localizedName(locale:)` · `BibleReference.text(locale:)` · `Translation.displayName(locale:)` · 모듈 `…Catalog.string(_:locale:)`)를 쓴다.
- 모듈마다 카탈로그 완결성 시험(`<모듈>LocalizationCatalogTesting`)이 ko 키가 en 에 모두 있는지 본다.

### 8-4. 영어 본문 글꼴 (결정 12)

나눔 3종(`SentenceSetting` 의 명조 · 고딕 · 꽃 손글씨)을 그대로 쓴다 — 라틴 글자가 들어 있다. 새 글꼴 리소스 · 라이선스 검토가 없다.
M1 에서 모양을 보고 어색하면 글꼴 추가는 후속 작업으로 한다.

**글꼴 표시 이름(결정 18, 2026-10-12)** — 본문 설정의 글꼴 고르기에 보이는 이름을 번들 글꼴 파일의 패밀리 이름에 맞춘다. 저장값(`FontCase` rawValue)은 그대로다.

| `FontCase` | 파일 | ko | en | 2.0 까지 ko 표기 |
|---|---|---|---|---|
| `myeongjo` | `NanumMyeongjo.ttf` | 나눔명조 | Nanum Myeongjo | 나눔명조 |
| `gothic` | `NanumGothic.ttf` · `NanumGothicBold.ttf` | **나눔고딕** | Nanum Gothic | 나눔바른고딕 — 앱에 넣지 않은 다른 글꼴 이름이었다(레이어 4 t4c 가 바로잡음) |

- 이름은 Domain `FontCase.title(locale:)` 한 곳에서 꺼낸다 — CarveFeature 가 따로 번역하던 글꼴 이름을 이것으로 합치는 일과 「나눔손글씨 꽃내음」 반영은 레이어 5 t5a 다.

### 8-5. 앱 언어 바꾸기 (결정 20, 2026-10-12)

- 설정 사이드바 「화면」 묶음에 **「언어」** 행을 둔다(`SettingsFeature.SidebarItem.language` · `LanguageSettingsFeature`). 행 값과 화면은 지금 앱 언어를
  그 언어 이름(「한국어」 · 「English」)으로 보이고, 「iPad 설정에서 바꾸기」 가 설정 앱의 이 앱 화면(`UIApplication.openSettingsURLString`)을 연다.
- **언어는 앱 안에 저장하지 않는다 — iOS 앱별 언어(설정 › 새기다 › 언어)를 그대로 쓴다.** 바꾸면 iOS 가 앱을 새로 시작하므로 화면 · 권 이름(결정 3) · 날짜 서식이
  한꺼번에 바뀐다. 지금 언어는 모듈 번들이 고른 현지화(`Bundle.module.preferredLocalizations`)로 읽는다(`AppLanguage.current`).
- 기기의 선호 언어가 하나뿐이면 iOS 가 앱 화면의 「언어」 항목을 숨기므로, 앱 Info.plist 에 `UIPrefersShowingLanguageSettings = YES` 를 켠다
  (`Plugins/ProjectDescriptionHelpers/InfoPlist.swift`).
- 번역본은 앱 언어와 따로다 — 헤더 제목 메뉴(결정 19). 언어 화면 설명에도 적는다.
- 기각: 앱 안 고르기(시스템 · 한국어 · English). 설정 앱의 앱별 언어도 앱 자기 UserDefaults 의 `AppleLanguages`(예 `["en-KR", "ko-KR"]`)에 저장되므로
  같은 키를 쓰면 효과는 같다(2026-10-12 시뮬레이터 확인). 그러나 설정 앱에서 바꾸면 iOS 가 앱을 종료해 바로 새 언어로 열리는 반면, 앱 안에서 바꾸면
  사용자가 직접 앱을 닫았다 열어야 한다 — 앱이 스스로 끝내는 `exit()` 는 Apple 이 금한다. 재시작 없이 바로 바꾸려면 `String(localized:)` · 카탈로그 도우미 ·
  날짜 서식 · Domain 권 이름 전체가 앱 전역 언어 값을 받아야 해 범위가 크다. 사용자가 설정 앱 쪽을 그대로 두기로 했다(2026-10-12).
- 실행 인자: `-UITestRoute settings/language`.

## 9. 수동 확인 M1~M4 (결정 14)

자동 시험(레이어마다 통합 브랜치 게이트) 밖에서 사람이 보는 것이다. **M4 는 결정 1 의 안전성을 실제로 확인하는 유일한 길이라 출시 전 관문이다.**

| # | 시나리오 | 확인할 것 |
|---|---|---|
| M1 | 번역본 번갈아 필사 (iPad 시뮬레이터) | 같은 장을 개역개정 · KJV · BSB 로 번갈아 쓰고 전환 · 재실행한다. 필기가 섞이지 않는지, 절 위치가 유지되는지(없는 절이면 앞 절로 가는지) 본다. 영어 본문 줄바꿈과 나눔 글꼴 모양도 본다(결정 12 후속 판단) |
| M2 | 영어 기기 언어로 화면 훑기 | `-AppleLanguages (en)` 로 탐색 · 필사 · 즐겨찾기 · 차트 · 설정 전체를 `-UITestRoute` 로 연다. 잘림과 한국어가 남은 곳이 없는지 본다. 한국어 기기에서 KJV 참조가 「창세기 1장 1절 · KJV」 인지도 본다 |
| M3 | 위젯 · 이미지 · 백업 (영어) | KJV 절을 위젯에 담고 눌러 KJV 절로 오는지 본다. 이미지 저장의 출처 표기를 본다. 백업 내보내기 → 불러오기에서 KJV 필사가 KJV 로 돌아오는지 본다 |
| M4 | 2.0.0 기기와 iCloud 공존 (**출시 전 관문**) | dev 저장소 · 같은 계정에서 2.0.0 빌드 기기와 새 빌드 기기를 동기화한다. 영어 필사 · 즐겨찾기가 2.0.0 에서 보이지 않고, 크래시와 한국어 절 혼입이 없는지 본다(결정 1 의 실제 확인) |

- M4 는 Debug 빌드 · dev 저장소 범위다. 두 기기 방식은 [호환성 시험 계획](./icloud-sync-compatibility-test-plan.md) 단계 A(CK-A0 ~ A5)의 OLD · CURRENT 와 같고,
  업데이트 · CloudKit 표본이 든 기존 시뮬레이터는 쓰지 않는다. 운영 저장소 · App Group 을 건드리면 먼저 백업하고 끝나면 되돌린다.
- **M4 에서 함께 볼 것(§3-2):** 2.0.0 의 주간 요약 「최근 절」 에 영어 행이 창세기로 보이는지, 누르면 어디로 가는지(창세기에 없는 장 포함) — 쓰기 · 크래시가 없으면
  알려진 한계로 둔다(§10). 차트 날짜별 절 수에 영어 필사가 드는 것은 예상 동작이다.
- 실행 인자: 영어로 열기 `-AppleLanguages "(en)" -AppleLocale en_US`, 번역본 지정 `-UITestChapter '{"title":"1-01Genesis.txt","chapter":1,"translation":"KJV"}'`
  ([실기기 · 시뮬레이터 요령](./device-simulator-verification.md) 「화면 바로 열기」).

## 10. 알려진 한계

| 한계 | 이유 · 후속 |
|---|---|
| **위젯의 권 이름은 지정할 때의 언어로 남는다** | 위젯은 Domain 을 링크하지 않아 앱이 지정할 때 만든 문자열(`VerseWidgetPayload.bookDisplayName`)을 그대로 쓴다. 기기 언어를 바꿔도 다시 지정하기 전까지 그대로다 |

| **영어 본문 글꼴은 나눔 그대로다** | §8-4. M1 뒤 후속 판단 |
| 2.0.0 · 1.3.0 의 주간 요약 「최근 절」 이 영어 행을 창세기로 보인다 | 구버전 코드의 `?? .genesis`(§3-2). 이미 나간 버전이라 고칠 수 없다. M4 에서 실제 모습을 확인한다 |
| 2.0.0 · 1.3.0 의 차트 날짜별 절 수에 영어 필사가 든다 | 구버전 활동 조회는 권을 보지 않는다(§3-2) |
| 개역개정 출처 표기가 비어 있다 | 허락 근거를 확인한 뒤 채운다(§2-1 · §6-3) |
| 지금 번역본은 기기마다다 | `@Shared("title")` 은 기기 설정이라 다른 iPad 는 따라오지 않는다(결정 4) |

| App Store 영어 메타데이터는 없다 | 범위 밖(결정 8) |
